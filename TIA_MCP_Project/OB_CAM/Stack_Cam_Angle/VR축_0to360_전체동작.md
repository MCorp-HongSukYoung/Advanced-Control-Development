## 0) 한 줄 결론

> **VR03 1회전(0°→360°) = 4-Phase 사이클 중 RUN Phase 1회.**  
> LC_RUN과 RA_RUN이 각각 VR03을 1회전시키며, P&P 12축 + Reverse 4축 + Stack Table Swing 4축이 VR03 슬레이브로 동기된다. Reverse **R(회전)축**은 GET(20°~180°)·PUT(180°~340°)·Dwell 세 구간으로 동작하지만, **Z(승강)축은 구간이 다르다** — GET Z는 0°~22° 급강하, PUT Z는 252°~274° 하강 (§5).

## 1) 4-Phase 사이클 전체 구조

```
[LC_RUN] → [LC_STACK] → [RA_RUN] → [RA_STACK]  × N층
  VR03↑       VR04↑       VR03↑       VR04↑
```

| Phase | 마스터 | 주 동작 | Reverse 역할 |
|-------|--------|---------|-------------|
| **LC_RUN** | VR03 | Cathode PUT + Anode GET | Cathode Reverse PUT(180°~340°) / Anode Reverse GET(20°~180°) |
| **LC_STACK** | VR04 | Mandrel Cathode 전극 압착 | CAM 비활성 |
| **RA_RUN** | VR03 | Anode PUT + Cathode GET | Anode Reverse PUT(180°~340°) / Cathode Reverse GET(20°~180°) |
| **RA_STACK** | VR04 | Mandrel Anode 전극 수령·압착 | CAM 비활성 |

> VR01/VR02(Dsheet 검출)는 4개 Phase 내내 상시 회전.  
> ※ 표의 Reverse 괄호 각도는 **R(회전)축** 이송 구간 기준 — Z(승강)축은 별도의 좁은 다이브 구간(§5).

## 5) Reverse P&P CAM 각도 범위 (CAM export 실측 — `Reverse_PP_Motion_Profile.md` §4)

> ⚠️ **교정 (2026-05-21)**: R(회전)축과 Z(승강)축은 **서로 다른 VR03 각도 범위**에서 동작한다. (이전 "동일 범위" 서술은 CAM 커브와 불일치 — 오류.)

### 5-1. R(X)축 — 넓은 이송 구간

| 구간 | VR03 범위 | LC_RUN 동작 | RA_RUN 동작 |
|------|-----------|------------|------------|
| GET (수령) | **20°~180°** (이동) | Anode Reverse R (Axis27) — 다음 Anode 전극 수령 | Cathode Reverse R (Axis12) — 다음 Cathode 전극 수령 |
| PUT (전달) | **180°~340°** (이동) | Cathode Reverse R (Axis12) — AlignTable로 이송 | Anode Reverse R (Axis27) — AlignTable로 이송 |
| Dwell | 0°~20°, 340°~360° | 위치 유지 | 위치 유지 |

### 5-2. Z(승강)축 — 좁은 다이브 구간

| 동작 | VR03 범위 | 비고 |
|------|-----------|------|
| **GET Z** | **0°~22° 급강하** → 22°~360° 최저 유지 | 사이클 초반에 빠르게 하강해 수령 위치 확보 |
| **PUT Z** | 0°~252° 상부 Dwell → **252°~274° 하강** → 274°~360° 최저 유지 | 사이클 후반(약 3/4 지점)에 하강해 안착 |

> 따라서 GET은 Z 다이브(0°~22°)가 R 이동(20°~180°)보다 먼저 끝나고, PUT은 Z 하강(252°~274°)이 R 이동 완료(340°)보다 먼저 시작된다 — Z·R 구간이 어긋난 복합 동작.

### 비전 트리거 교정 근거

LC_RUN에서 **RA Vision이 먼저(80°), LC Vision이 나중(170°)** 트리거되는 이유:

```
LC_RUN (VR03 회전 중)            RA_RUN (다음 Phase)
  80°  → RA Vision 사전 검사  →  RA_RUN 시작 시 검사 데이터 준비 완료
  170° → LC Vision 검사        →  이번 LC 전극 품질 확인 완료
```

반대로 RA_RUN Phase에서는 **LC Vision이 80°, RA Vision이 170°** 에 트리거됩니다(`FB_Auto_Sub1_Stack_300` 확인).  
각 Phase가 **상대방 Vision을 먼저 쏘는 교차(Cross) 구조**로 다음 Phase 시작 전 검사 데이터를 미리 준비합니다.

## 8) GET/PUT 교차 구조 — LC_RUN 기준

### 한 사이클 안의 두 파이프라인

```
[ LC 전극 흐름 ]
매거진 ─▶ LC PP1(픽업) ─▶ Reverse Table(반전+Surface Vision) ─▶ AlignTable(직접 전달)
                                                                        │
                                                                  Align Vision
                                                                        │
                                                              LC PP2(픽업) ─▶ Stack Table ─▶ Gap Vision

[ RA 전극 흐름 ]
매거진 ─▶ RA PP2(픽업) ─▶ Reverse Table(반전+Surface Vision) ─▶ AlignTable(직접 전달)
                                                                        │
                                                                  Align Vision
                                                                        │
                                                              RA PP1(픽업) ─▶ Stack Table ─▶ Gap Vision
```

> 두 흐름은 **VR03 한 바퀴 동안 동시에 진행** (2-단 파이프라인).  
> **이번 사이클에 적층되는 전극 = 이전 사이클 Reverse 완료 전극**.  
> **이번 사이클 GET 전극 = 다음 사이클에 적층**.

> 두 파이프라인은 **VR03 한 바퀴 동안 동시에 진행**.  
> **이번 사이클에 적층되는 전극 = 이전 사이클 Reverse 완료 전극**.  
> **이번 사이클 GET 전극 = 다음 사이클에 적층**.

### GET/PUT 역할 매핑

| 사이드 | PP1 헤드 | PP2 헤드 | Reverse (LC_RUN) |
|---|---|---|---|
| **LC (Cathode)** | 매거진 픽업 → Reverse Table 전달 | AlignTable 픽업 → Stack Table 전달 | Axis12/11 **PUT** (180°~340°) → AlignTable 직접 전달 |
| **RA (Anode)** | AlignTable 픽업 → Stack Table 전달 | 매거진 픽업 → Reverse Table 전달 | Axis26/27 **GET** (20°~180°) → AlignTable 직접 전달 |

> RA_RUN에서는 Reverse 역할 반전: Axis26/27 PUT(180°~340°) / Axis12/11 GET(20°~180°)

## 9) 각 흐름 서술

### 9-1. LC (Cathode) — `PP1 → Reverse Table → AlignTable → PP2 → Stack Table`

> CAM export + FB_Camin_STACK_LC/RA_RUN + FB_Auto_Sub1_Stack_200 코드 기반.  
> 파이프라인 구조이므로 각 단계는 서로 다른 VR03 사이클(Phase)에서 진행됨.

| # | 동작 | Phase | VR03 각도 |
|---|---|---|---|
| 1 | **매거진 픽업** `LC PP1`(Axis13/14) — Z 최저 = 흡착 | LC_RUN | **VR03 = 180°** |
| 2 | **Reverse Table 전달** `LC PP1` — Z 최저 = 안착, VAC 전환 | RA_RUN | **VR03 = 180°** |
| 3 | **LC Surface Vision** `DB_1st/2nd_Surface_Vision_LC` 트리거 | RA_RUN | **VR03 ≥ 80°** (RA_RUN에서 LC측은 80°) |
| 3′| **RA Vision 사전 준비** `DB_1st/2nd_Surface_Vision_RA` 트리거 | RA_RUN | **VR03 ≥ 170°** |
| 4 | **Reverse 반전** `ReverseR_GET`(Axis12) R 이동 — 전극 수신 후 회전 | RA_RUN | **VR03 = 20°~180°** |
| 5 | **AlignTable 직접 전달** `ReverseZ_PUT`(Axis11) Z 최저 = 안착, VAC 전환 | LC_RUN | **VR03 = 252°~274°** |
| 6 | **Align Vision** `DB_Align_Vision` Trg[18] | LC_RUN | **VR03 120°~180°** (다음 사이클) |
| 7 | **Stack Table 전달** `LC PP2`(Axis15/16) — Z 최저 = 안착 | LC_RUN | **VR03 = 180°** |
| 8 | **Gap Vision** `DB_Gap_Vision_LC` Trg[0] | **LC_STACK** | **VR04 ≥ 8°** (FB_400 step430) |

> **Phase 주의**: 1번(매거진 픽업)과 7번(Stack Table 전달)은 같은 LC_RUN이지만 서로 다른 사이클 — 한 전극이 매거진을 떠나 Stack Table에 도달하기까지 LC_RUN → RA_RUN → LC_RUN 3개 사이클을 거침.

```
LC_RUN (사이클 N)    RA_RUN (사이클 N)    LC_RUN (사이클 N+1)
────────────────────────────────────────────────────────────
① PP1 매거진 픽업    ② PP1 Reverse 전달   ⑤ Reverse→Align 전달
   (180°)              (180°)               (252°~274°)
⑦ PP2 Stack 전달    ③ LC Vision 확인      ⑥ Align Vision
   (180°)              (≥80°)               (120°~180°)
                    ④ Reverse 반전
                       (20°~180°)
```

### 9-2. RA (Anode) — `PP2 → Reverse Table → AlignTable → PP1 → Stack Table`

LC와 거울 대칭. **PP1/PP2의 GET/PUT 역할이 반대**임에 주의.

| # | 동작 | Phase | VR03 각도 |
|---|---|---|---|
| 1 | **매거진 픽업** `RA PP2`(Axis30/31) — Z 최저 = 흡착 | LC_RUN | **VR03 = 180°** |
| 2 | **Reverse Table 전달** `RA PP2` — Z 최저 = 안착, VAC 전환 | RA_RUN | **VR03 = 180°** |
| 3 | **RA Surface Vision** `DB_1st/2nd_Surface_Vision_RA` 트리거 | LC_RUN | **VR03 ≥ 80°** |
| 3′| **LC Vision 사전 준비** `DB_1st/2nd_Surface_Vision_LC` 트리거 | LC_RUN | **VR03 ≥ 170°** |
| 4 | **Reverse 반전** `ReverseR_GET`(Axis27) R 이동 — 전극 수신 후 회전 | LC_RUN | **VR03 = 20°~180°** |
| 5 | **AlignTable 직접 전달** `ReverseZ_PUT`(Axis26) Z 최저 = 안착, VAC 전환 | RA_RUN | **VR03 = 252°~274°** |
| 6 | **Align Vision** `DB_Align_Vision` Trg[16] | RA_RUN | **VR03 120°~180°** (다음 사이클) |
| 7 | **Stack Table 전달** `RA PP1`(Axis28/29) — Z 최저 = 안착 | RA_RUN | **VR03 = 180°** |
| 8 | **Gap Vision** `DB_Gap_Vision_RA` Trg[0] | **RA_STACK** | **VR04 ≥ 8°** (FB_500 step530) |

> **비전 교차**: LC_RUN 중 RA Vision(80°)이 먼저, LC Vision(170°)이 나중 — 파이프라인에서 다음 사이클 전극을 미리 검사하는 구조.

### 9-3. Stack Table Swing Roller — 분리막 덮기

> 실측 CAM export 기반 (Cam_STACK_Swing1Z_LC, Cam_STACK_Swing1R_LC).

1. **0°~72° · 압착**: Z 하강 (0→1, CubicSpline) — 롤러가 분리막에 압착. R은 36°까지 홈 유지.
2. **36°~324° · 스윕**: R 회전 (0→1, CubicSpline) — 분리막을 전극 위로 밀어 씌움. (Z는 72°~288° 완전 압착 상태 유지.)
3. **288°~360° · Z 복귀**: Z 상승 (1→0) — 롤러 들어 올림. R은 324°에 완전전개 도달 후 360°까지 유지.
4. **STACK Phase · 홈 복귀**: CAMOUT 후 Z·R 양축 모두 홈 복귀 (CAM 내에서는 복귀 없음).

## 10) 핵심 포인트 정리

| # | 포인트 |
|---|--------|
| 1 | **VR03 1회전 = RUN Phase 1회** — 4-Phase 사이클에서 LC_RUN과 RA_RUN 각각 VR03 1회전 |
| 2 | **Reverse 각도(R축)**: GET 20°~180°, PUT 180°~340°, Dwell 0°~20°·340°~360° — **Z축은 별도**: GET Z 0°~22° 급강하, PUT Z 252°~274° 하강 (§5) |
| 3 | **비전 교차 구조**: LC_RUN 중 RA Vision이 먼저(80°), LC Vision이 나중(170°) — 다음 Phase 사전 준비 |
| 4 | **Align Vision은 VR03 120°~180° 구간** (RUN Phase) — `Trg[18]`(LC_RUN)/`Trg[16]`(RA_RUN). STACK Phase에는 VR04 8°~350°(`Trg[10]`) 별도 발화. ("180° 단일 시점·PP Z 최저 동시"는 부정확) |
| 4′| **Gap Vision은 STACK(VR04) Phase** — `FB_Auto_Sub1_Stack_400/500`에서 VR04 ≥ 8°로 트리거 (RUN/VR03 아님) |
| 5 | **CAMIN 이중 신호**: `STACK_LC_RUN_CAMIN`(주 스태킹) + `Single_LC_RUN_CAMIN`(버퍼 채우기) |
| 6 | **Phase 전환은 교차 게이트**: 반대편 캠이 시작 위치 대기 확인 후에만 전환 |
| 7 | **InSync에 Reverse 포함**: Reverse R/Z 동기 실패 시 Phase 전환 차단 |
| 8 | **2-단 파이프라인**: 이번 사이클 GET = 다음 사이클 적층 / 이번 사이클 PUT = 이전 사이클 GET 전극 |
